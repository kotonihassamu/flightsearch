# 定時実行の設定（毎日 7時前・18時前に届ける）

## 実行方式

通常は外部cronから `repository_dispatch` を送り、06:10 / 17:10 JST に検索を開始する。
外部cronの停止に備えて、GitHub Actions自身も06:30 / 17:30 JSTに
`schedule` を起動する。

`schedule` 実行時は、同じワークフローに直近2時間の正常な
`repository_dispatch` 実行があるかを自動確認する。見つかった場合は検索をスキップし、
見つからない場合だけフォールバック検索を行う。そのため、外部cronが正常な日は
LINE通知が二重にならない。

## なぜ外部cronを主系にするのか

GitHub Actions の `schedule` は**時刻どおりに動く保証がない**。専用の実行枠が無く、
世界中の他のジョブと同じキューに入るため、混雑時に大きく遅延する。

実測（2026年7月末〜8月・本リポジトリ）:

| 予定 | 実際の開始 | 遅延 |
|---|---|---|
| 06:15 | 07:12 / 07:12 / 07:16 / 07:18 / 07:28 | 57〜73分 |
| 18:15 | 19:48 / 19:49 / 20:20 / 20:35 / **21:35** | 93分〜**3時間20分** |

実行自体に約24分かかるので、通知が届くのは上記のさらに後になる。
「45分前に予約する」程度の対策では全く足りなかった。

GitHub公式も「schedule イベントは高負荷時に遅延しうる」と明記しており、
これは不具合ではなく**仕様**。待っても改善しない。

## 解決策: 時計を GitHub の外に出す

外部の無料cronサービスから GitHub API を叩き、`repository_dispatch` で起動する。
**dispatch 由来の実行はキュー待ちがほぼ無く、API呼び出しから数秒で始まる。**

```
cron-job.org（正確な時計）
   ↓ 06:10 / 17:10 JST に HTTPS POST
GitHub API (repository_dispatch)
   ↓ 数秒で起動
daily-flight-check ワークフロー（約24分）
   ↓
LINE通知（06:35頃 / 17:35頃）
```

これで **7時前・18時前** に確実に届く。

# 設定手順

## STEP 1. GitHub のトークンを作る

外部サービスから GitHub を操作するための鍵。**権限は最小限**にする。

1. https://github.com/settings/personal-access-tokens/new を開く
   （Settings → Developer settings → Personal access tokens → **Fine-grained tokens**）
2. 以下を設定:

   | 項目 | 値 |
   |---|---|
   | **Token name** | `flightsearch-cron` |
   | **Expiration** | 1年（期限切れ時は作り直し。カレンダーに入れておく） |
   | **Repository access** | **Only select repositories** → このリポジトリだけ選ぶ |

3. **Permissions** → Repository permissions で **Contents** を **Read and write** にする
   （`repository_dispatch` を送るのに必要。他は触らない）
4. **Generate token** をクリック
5. `github_pat_...` で始まる文字列が表示される。**この画面を離れると二度と見られない**ので、
   すぐ次のSTEPに進むか、安全な場所に一時保存する

> **なぜ Contents 権限か**: `repository_dispatch` API は Contents の書き込み権限を要求する
> （GitHubの仕様）。リポジトリを1つに絞っているので、影響範囲は限定される。

## STEP 2. cron-job.org に登録する

1. https://cron-job.org/en/ で無料アカウントを作る（メール確認あり）
2. ログイン後、**CREATE CRONJOB** をクリック

## STEP 3. 朝のジョブを作る

**COMMON タブ:**

| 項目 | 値 |
|---|---|
| **Title** | `flight 朝` |
| **URL** | `https://api.github.com/repos/<ユーザー名>/<リポジトリ名>/dispatches` |
| **Execution schedule** | Custom を選び、**毎日 06:10** |
| **Timezone** | **Asia/Tokyo** を選ぶ（重要） |

> URLの `<ユーザー名>/<リポジトリ名>` は自分のものに置き換える。
> 例: `https://api.github.com/repos/yourname/flightsearch/dispatches`

**ADVANCED タブ:**

| 項目 | 値 |
|---|---|
| **Request method** | **POST** |
| **Request body** | `{"event_type":"morning"}` |

**Headers**（3行追加する）:

```
Accept: application/vnd.github+json
Authorization: Bearer github_pat_ここにSTEP1のトークン
Content-Type: application/json
```

**SAVE** をクリック。

## STEP 4. 夕方のジョブを作る

STEP 3 と同じ手順で、違うのは3点だけ:

| 項目 | 値 |
|---|---|
| **Title** | `flight 夕` |
| **Execution schedule** | 毎日 **17:10**（Asia/Tokyo） |
| **Request body** | `{"event_type":"evening"}` |

## STEP 5. 動作確認

cron-job.org のジョブ一覧で、作ったジョブの **TEST RUN**（または実行ボタン）を押す。

**期待する結果:**

- cron-job.org 側: レスポンス **204 No Content**（成功。本文が空なのが正常）
- GitHub側: Actions タブに `daily-flight-check` の実行が**数秒以内**に現れる
- 約25分後: LINEに通知が届く

**失敗したときの見分け方:**

| レスポンス | 原因 |
|---|---|
| **401** | トークンが誤り／失効。STEP 1 をやり直す |
| **403** | トークンの権限不足。**Contents: Read and write** になっているか確認 |
| **404** | URLのユーザー名・リポジトリ名が違う。または対象リポジトリを選択していない |
| **422** | Request body の書式ミス。`{"event_type":"morning"}` を正確に |

## 届く時刻の目安

| | dispatch | 実行時間 | 通知が届く |
|---|---|---|---|
| 朝 | 06:10 | 約24分 | **06:35頃** |
| 夕 | 17:10 | 約24分 | **17:35頃** |

もっと早く届かせたい／余裕が欲しい場合は、cron-job.org 側の時刻を早めるだけでよい
（コードの変更は不要）。

逆に**実行時間そのものを短くしたい**なら `config.json` を調整する:

| 変更 | 効果 |
|---|---|
| `sleep_between_searches` を `[3, 7]` に | 約24分 → 約17分（Bot判定リスクは上がる） |
| `weekends_ahead` を `1` に | 検索が半分になり約12分（見る週末は1つだけになる） |
| 空港を減らす（`enabled: false`） | 減らした分だけ短縮 |

## GitHub の schedule はどうなっているか

`daily.yml` の `schedule:` はフォールバックとして有効化してある。
外部cronより30分遅く起動し、直近の外部実行が正常なら自動的にスキップする。
外部cron側で障害が起きた場合だけ検索を続行するため、何も通知されない状態を防ぎつつ、
通常時の二重通知も避けられる。

## 外部cronが止まっていないか確認する方法

cron-job.org には実行履歴（History）があり、失敗時にメール通知も設定できる。
アカウント設定で通知を有効にしておくと、止まったときに気づける。

簡易的には「朝の通知が来ない日が2日続いたら確認」でよい。
その際は Actions タブを見て、そもそも実行が始まっているかを確認する。

## 代替案（参考）

外部サービスを使いたくない場合:

| 方法 | 時刻の正確さ | PCの電源 | 備考 |
|---|---|---|---|
| **外部cron + dispatch**（本手順） | ◎ 数秒 | 不要 | 推奨 |
| GitHub schedule | △ 最大3時間遅延 | 不要 | 外部cron停止時のフォールバック |
| Windowsタスクスケジューラ | ◎ 正確 | **必要** | その時刻にPCが起動している必要がある |
| Raspberry Pi 等の常時稼働機 | ◎ 正確 | 常時ON | VPNも使える。最も自由度が高い |
